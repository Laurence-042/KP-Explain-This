# KP-Explain-This 第二轮迭代：控制器重构 + PDF + 重骰机制 + 动画

## 一、RoleController 同基类重构（核心，满足多真人PC/多LLM PC扩展）

新增 `src/core/controller.ts`，KP 与 PC 从引擎的硬编码分支改为**同一接口的两种实现**：

```ts
export interface RoleController {
  readonly role: RoleDef
  /** 引擎 → 控制器：请求一次行动（KP=生成/推进场景；PC=描述行动） */
  requestAction(req: ActionRequest, signal: AbortSignal): Promise<ControllerResponse>
  /** 是否同意重骰当前场景（多角色协商入口） */
  requestRerollConsent(): Promise<boolean>
  /** 响应已被引擎采纳（LLM 控制器修剪历史：只保留叙事，去掉 JSON 块） */
  onApplied(req: ActionRequest, response: ControllerResponse): void
  /** PC 行动被 Validator 驳回（人类控制器刷新 UI 提示） */
  onRejected?(reason: string): void
  /** 场景级回滚点（重骰时回滚世界状态与各自历史） */
  sceneCheckpoint(): unknown
  sceneRestore(cp: unknown): void
  abort(): void
}
```

- `HumanController`：requestAction/requestRerollConsent 挂起 Promise，由 UI（useGame 转发输入框/按钮）resolve；abort 时 reject。**不再由引擎提供 submitAction 特例**。
- `LlmKpController`：持有 kpSession，`requestAction` 按 req.kind（scene-opening / respond-action）组 prompt 并流式调用（onStream 回调透传引擎）；`requestRerollConsent` 返回 true（LLM KP 总会同意；接口保留，未来可真问 LLM 或接 LLM PC）；sceneCheckpoint/Restore 回滚 session 历史与摘要。
- **引擎变纯编排**：持有 `controllers: RoleController[]`，循环 = KP 开场 → 逐 PC 收集行动 → 验证 → 转 KP 推进 → 直到 scene_end。Validator 保持引擎的系统服务（裁判不是游戏角色，story 的同基类要求针对 KP/PC 扮演者）。快照/恢复时只序列化 controller 状态（KP=session 序列化，Human=空）。

## 二、重骰机制替代主动结束场景

- 移除"结束场景·翻页"按钮与 `engine.endScene()`。
- KP 输出 `scene_end: true` → 引擎**自动收尾**：系统日志 + 翻页动画 + 下一轮掷骰 + 新场景（KP prompt 强化收尾时机）。
- 新增"重骰本场景"：UI 按钮（带确认弹窗）= 玩家同意 → 引擎逐 controller 收集 consent（KP 即时 true）→ 全体同意后：abort 挂起请求 → 回滚各 controller checkpoint + world + log 到本轮开始 → 在当前页重掷骰子 → 重新开场。任一拒绝则提示并继续。

## 三、BookDocument 页导向重构 + PDF 支持

- 类型改为 `pages: BookPage[]`，每页 `{ text, words[], valid[] }`，词 offset **相对页文本**（高亮不再依赖全书连续原文）。`KeywordPick` 直接携带 `{pageIndex, offset, length, keyword, dieIndex, dieValue}`。
- `parseTxt`：分词后按每页词数切片，页文本=原文切片、页内偏移平移；`parsePdfPages(id, name, pageTexts)`：纯函数，真实页、页内分词，无字页保留（占页数，nearestValidPage 跳过）。跨页取词兜底逻辑保留（全局序扫描）。
- pdfjs 文本抽取放 `useBooks`（dynamic import + worker，仅导入 PDF 时加载，core 保持纯净可测）；`StoredBook` 泛化为 `{source: 'txt'|'pdf', text? | pageTexts?}`；存档 BookMeta 相应扩展（PDF 导出内嵌 pageTexts）。
- 开局面板：每页词数仅在所选书为 TXT 时生效（任一 PDF 则禁用并提示）；useGame.startGame 按 source 选择解析路径。

## 四、书架页数显示 + 骰子覆盖警告

- 书架项显示页数：TXT = 词数 ÷ 当前每页词数（随表单实时估算，导入时统计词数存入 meta）；PDF = 真实页数。
- 实时校验：`maxSum = diceCount × 10 < 所选书总页数` 时显示警告："该书共 N 页，当前骰子点数和最多 M，第 M+1 页之后的页永远不会被翻到——建议增加骰子数或（TXT）减小每页词数"（非阻断）。

## 五、真正的动画

- `DiceOverlay.vue`（新）：掷骰时全屏遮罩，CSS 3D 六面骰子立方体翻滚（tumble keyframes）逐个落定显示点数 → 命中关键词标签依次弹入 → "翻到第 N 页"提示，~2.2s 自动收起（可点击跳过）。init-roll 与每轮 roll 事件触发，与 LLM 生成并行。
- `BookView` 翻页覆盖层：一张"纸"从右向左 `rotateY(0→-180deg)`（transform-origin: left），动画中点切换页内容，flip 事件驱动重放——肉眼明确可见。

## 六、state_changes 嵌套解包修复

`sanitizeStateChanges` 检测顶层 `state_changes` 键且值为对象时解包内层再清洗（KP 有时把整个对象多包一层；json-out 的识别已兼容此形态）。补单测。
