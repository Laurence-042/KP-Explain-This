# 加入 LLM PC：三变种控制器架构（本地 / LLM / 在线占位）

## 架构总览

`RoleController` 接口不变（它就是三种变体的共同契约，也是未来联机的接入点——本轮仅文档占位，不写远程死代码）。`controller.ts` 重构为：

```
RoleController（接口，不变）
├── HumanController        接入本地玩家（不变）
├── BaseLlmController      LLM 变种的共享机制：持有 LLMSession、
│   ├── LlmKpController       requestRerollConsent→true、sceneCheckpoint/Restore
│   └── LlmPcController    （历史长度+摘要回滚）、abort
└── （在线玩家：未来实现 RemoteController 即插即用，引擎零改动，AGENTS 注明）
```

两个产品形态（按你的要求）：
- **独立 LLM PC**：开局面板可增删若干 LLM 玩家（名字+书），每轮自主行动、过 Validator、被驳回自动带理由重写。
- **LLM 代写（本地玩家辅助）**：行动输入框旁加「LLM 代写」按钮，用 PC-LLM 连接一次性生成草稿**填入输入框**，玩家可修改后照常提交（不自动发送）。

配置：设置抽屉新增第三条连接「LLM 玩家」（与 KP/Validator 并列，Base URL/Key/模型/温度，带一键复制 KP 连接）；所有 LLM PC 与代写共用此连接，但各 LLM PC 有独立会话/历史/温度。旧配置无此字段时读取边界归一化为默认值（沿用 schema 兼容惯例）。

## 一、core/controller.ts

- 抽 `BaseLlmController`（abstract）：`session` 只读字段、`requestRerollConsent() → true`、`sceneCheckpoint/sceneRestore`（historyLength+summaryText 截断）、`abort()` 空实现——全部从现 `LlmKpController` 上提。
- `LlmKpController extends BaseLlmController`：行为不变。
- 新增 `LlmPcController extends BaseLlmController`：
  - `requestAction`（kind `pc-act`）：`session.params.systemPrompt = () => buildPcSystemPrompt(...)`；user 消息 = `buildPcActionUser(req.sceneNarrative)`，若上次被驳回则用 `buildPcRetryUser(..., reason)` 并清掉记录；`session.send(..., stage 'pc-act')`；剥掉输出里可能出现的 markdown 围栏后返回。
  - `onRejected(reason)`：暂存理由，下一次请求带上。
  - `onApplied`：no-op（会话历史保留原文即可，无需 amend）。

## 二、core/prompts.ts（新增 PC 侧 prompt）

- `PC_SYSTEM_PROMPT`：你是即兴游戏中的玩家 PC「角色名」，不是主持人；写 1–3 句（约 50–120 字）回应；**全部关键词要有痕迹**（字面出现或任何相关展开：同义/指代/联想——与 Validator 宽松标准同一口径，禁止机械罗列）；任何形式合法（行动/对话/观察/内心独白）；不替 KP/NPC 做重大决定、不凭空获得物品、不瞬移，裁决权留给 KP。
- `buildPcSystemPrompt(roleName, world, keywords, round)` / `buildPcActionUser(sceneNarrative)` / `buildPcRetryUser(sceneNarrative, reason)`（"上一回应被驳回：{reason}，换一种写法"）。
- `buildPcAssistMessages(roleName, world, keywords, round, sceneNarrative)`：本地玩家「代写」的一次性消息组（同一标准，"为玩家草拟"），无会话状态。

## 三、core/engine.ts

- `ActionRequest` 增加可选 `sceneNarrative?: string`；`collectValidatedAction` 传入 `this.currentSceneNarrative`（HumanController 忽略，LlmPpController 需要）。
- 行动被采纳后补调 `pc.onApplied(req, text)`（接口语义补全，Human/LlmPc 均 no-op）。
- **LLM PC 生成失败处理**：`pc.requestAction` 的 catch 区分 AbortError（维持现状=按中止处理）与其他错误→发 error 事件 + `interrupted` phase + `waitForRetry` 后重试（对齐 kpAct 的中断恢复路径；否则 LLM PC 网络错误会被静默吞掉、主循环误停）。
- **驳回重生成的护栏**：同一行动连续 3 次被 Validator 驳回 → warning 日志 + `interrupted`（防止无限重生成烧 token）；「重试生成」重置计数。
- `EngineEvent` 增加 `{ type:'pc-acting'; roleId; roleName; active:boolean }`：LLM PC 生成前/后发出，UI 显示「XX 正在行动…」。

## 四、core/save.ts

- `SaveFileV1` 增加可选 `pcSessions?: Record<string, SerializedSession>`（RoleId → LLM PC 会话）。
- `buildSave` 5 个位置参数改为对象参数（顺势清理）；`isValidSave` 校验存在时的结构；`decodeSaveFile` 对缺失字段宽容（旧档照常载入，version 仍为 1，向后兼容）。

## 五、配置与设置 UI

- `types.ts` `GameConfig` 增 `pcLlm: ConnectionConfig`（默认温度 0.8）；`useConfig.load()` 归一化旧数据。
- `SettingsDrawer.vue` 增第三组「LLM 玩家」连接（复用现有表单块结构 + `useModels` 实例 + 一键复制 KP 连接按钮）。
- i18n：`pcLlmSection/pcLlmHint` 等。

## 六、composables/useGame.ts

- `StartSetup` 增 `llmPcs: Array<{ name: string; bookId: string }>`；角色 id：本地 `pc-a`，LLM PC `pc-llm-1..n`（`RoleDef.controller: 'llm'`——类型已支持）。
- 每个 LLM PC 建独立 `LLMSession`（pcLlm 连接，`pcLlmSessions: Record<RoleId, LLMSession>`）；`applyConfig` watch 同步更新它们的 client/params。
- `startGame`：有 LLM PC 时校验 pcLlm 连接就绪。
- `restoreFromSave`：按 `role.controller` 映射（kp→LlmKpController；pc+human→HumanController；pc+llm→LlmPcController，恢复 `save.pcSessions[role.id]`，旧档缺失则空会话）。
- `buildSaveFile` 序列化 pcSessions。
- **代写**：`requestAssist(): Promise<boolean>` —— 用 pcLlm 连接的 `client.complete`（stage `pc-assist'`）+ `buildPcAssistMessages(engine.currentSceneNarrative, ...)` 生成草稿，写入 `assistInsert: { seq, text }` ref。
- `pc-acting` 事件 → `pcActing` ref 供 UI chip。

## 七、开局面板 / 输入框 / 主界面

- `SetupPanel.vue`：保留 KP 书 + 本地玩家（名字+书）+ 骰子/每页词数；新增「LLM 玩家」区：动态行（名字+书选择）+ 添加/删除按钮，默认名 玩家B/玩家C…；`canStart` 在有 LLM PC 时加验 pcLlm 连接。
- `ActionComposer.vue`：「LLM 代写」按钮（MagicStick 图标，canSubmit 且非 running 时可用），emit `assist` → App.vue 调 `game.requestAssist()`；`assistInsert` 作 prop 传入，watch 合并进 draft 并聚焦（可编辑后手动发送）。`pcActing` chip 显示在输入框上方。
- App.vue：书页 tab / 关键词条已按角色数组渲染，多 PC 自动适配，只加代写与 chip 的接线。

## 八、测试 / 文档 / 验证

- 单测：engine.test 注入**真实 LlmPcController**+monkeypatch stream——LLM PC 行动→验证→KP 推进（roleName 透传）；驳回→重写请求含驳回理由→通过；重骰回滚截断 PC 会话；生成失败→interrupted→重试成功；3 次驳回护栏。save.test：pcSessions 往返 + 旧档兼容。buildSave 签名改动的既有用例同步更新。
- AGENTS.md：三变种控制器图、pcLlm 连接、代写、pcSessions；README：玩法与设置说明。
- 浏览器 E2E（mock LLM server）：本地+LLM PC 双人局跑通、代写填入输入框、重骰回滚、存档恢复含 LLM PC；结束后清理浏览器测试数据与 mock 进程（惯例）。
- 全程 `npm test` + `npm run build` 全绿后 git 提交。

## 已知边界（本轮不做）

- 多个本地玩家（输入框按行动者路由）——引擎本就支持，UI 路由另立项。
- 在线玩家仅架构占位；LLM 代写不自动提交（玩家保留最终决定权）。
